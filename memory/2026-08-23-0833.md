## 🔌 Transport MCP disponibili

MCP usa **JSON-RPC 2.0**, non REST. I transport supportati:

| Transport | Come funziona | Quando usarlo |
|-----------|---------------|---------------|
| **stdio** | stdin/stdout locale | Server locali (npx, uvx, script) |
| **SSE** | Server-Sent Events HTTP | Server remoti read-only/push |
| **Streamable HTTP** | HTTP bidirezionale streaming | Server remoti con chiamate tool |

## 📡 Anatomia protocollo MCP

**Non è REST** perché:

```json
// MCP usa JSON-RPC 2.0
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "read_file",
    "arguments": { "path": "/foo/bar.txt" }
  },
  "id": 1
}

// Risposta
{
  "jsonrpc": "2.0",
  "result": { "content": "..." },
  "id": 1
}
```

**REST tradizionale** sarebbe:
```http
POST /api/files/read
Content-Type: application/json

{"path": "/foo/bar.txt"}
```

## ✅ Come fare integrazione REST → MCP

Se hai un'API REST e vuoi esporla via MCP:

### Opzione 1: **Wrapper MCP server custom**

Crei un server MCP stdio/HTTP che traduce MCP → REST:

```javascript
// server.js (stdio MCP)
const { Server } = require('@modelcontextprotocol/sdk/server');
const server = new Server({ name: 'my-rest-wrapper' });

server.tool('get_data', async (args) => {
  // Chiama la tua API REST
  const res = await fetch('https://api.example.com/data', {
    method: 'POST',
    body: JSON.stringify(args)
  });
  return await res.json();
});

server.connect();
```

Poi:
```bash
openclaw mcp add myapi --command node --arg server.js
```

### Opzione 2: **Streamable HTTP diretto**

Se controlli il server, implementa Streamable HTTP MCP:
- Accetta POST su `/mcp`
- Parla JSON-RPC 2.0
- Restituisce stream HTTP

È più vicino a REST ma non identico.

### Opzione 3: **SSE gateway**

Server intermedio che:
1. Riceve chiamate MCP (JSON-RPC)
2. Traduce in REST calls
3. Restituisce via SSE

## 🔍 Differenza chiave: Risorse vs Procedure

### REST (Resource-based)
```http
# Ogni URL = una risorsa
GET    /api/users/123        # Leggi user
POST   /api/users            # Crea user
PUT    /api/users/123        # Aggiorna user
DELETE /api/users/123        # Cancella user

# Verbo HTTP = azione semantica
```

### JSON-RPC 2.0 (Procedure-based)
```http
# UN solo endpoint per tutto
POST /rpc

# Body dice cosa fare
{"jsonrpc":"2.0","method":"getUser","params":{"id":123},"id":1}
{"jsonrpc":"2.0","method":"createUser","params":{...},"id":2}
{"jsonrpc":"2.0","method":"deleteUser","params":{"id":123},"id":3}

# Verbo HTTP = sempre POST (tunnel)
```

## 📋 Tabella confronto

| Aspetto | REST | JSON-RPC 2.0 |
|---------|------|--------------|
| **Trasporto** | HTTP | HTTP (POST sempre) |
| **Formato** | JSON/XML/altri | JSON (sempre) |
| **Endpoint** | Multipli (`/users`, `/files`) | Singolo (`/rpc`) |
| **Azione** | Verbo HTTP (GET/POST/PUT/DELETE) | Campo `method` nel body |
| **Risorsa** | URL path (`/users/123`) | Parametro JSON (`{"id":123}`) |
| **Stateless** | Sì (principio REST) | Dipende (non garantito) |
| **Cache HTTP** | Naturale (GET cacheable) | No (tutto POST) |

## 💡 Perché JSON-RPC NON è REST

**1. Viola principi REST:**
```http
# REST: URL identifica risorsa
GET /api/document/xyz.txt

# JSON-RPC: risorsa è parametro
POST /rpc
{"method":"readFile","params":{"path":"xyz.txt"}}
```

**2. Non sfrutta HTTP:**
- REST: GET = safe/idempotent, cache browser
- JSON-RPC: tutto POST = niente cache, niente semantica HTTP

**3. Filosofia diversa:**
- REST → "navighi risorse" (web-like)
- JSON-RPC → "chiami funzioni remote" (RPC-like)

## 🎯 Analogia pratica

**REST = libreria:**
- Scaffali = URL
- Ogni libro = risorsa
- Vai allo scaffale giusto

**JSON-RPC = bibliotecario:**
- Chiedi al bancone (sempre POST /rpc)
- Dici cosa vuoi ("method": "dammiLibro")
- Parametri = dettagli richiesta

## ✅ Quindi per MCP?

Sì, **tecnicamente viaggia su HTTP**, ma:

```javascript
// Non puoi fare curl REST-style:
curl https://mcp-server.com/read_file?path=foo.txt  // ❌

// Devi fare JSON-RPC:
curl -X POST https://mcp-server.com/rpc \

```

**In sintesi:** JSON-RPC usa HTTP come trasporto, ma **non è REST** perché ignora risorse/verbi HTTP e usa un modello RPC puro.

## ✅ MCP server in PHP (esempio minimo)

```php
<?php
// mcp-server.php

header('Content-Type: application/json');

// Leggi richiesta POST
$input = json_decode(file_get_contents('php://input'), true);

// Validazione JSON-RPC 2.0
if ($input['jsonrpc'] !== '2.0') {
    http_response_code(400);
    exit(json_encode(['error' => 'Invalid JSON-RPC version']));
}

$method = $input['method'];
$params = $input['params'] ?? [];
$id = $input['id'];

// Routing metodi MCP
switch ($method) {
    case 'tools/list':
        $result = [
            'tools' => [
                ['name' => 'get_user', 'description' => 'Leggi dati utente'],
                ['name' => 'create_order', 'description' => 'Crea ordine']
            ]
        ];
        break;
    
    case 'tools/call':
        $toolName = $params['name'];
        $args = $params['arguments'];
        
        // Chiama la tua logica
        $result = handleToolCall($toolName, $args);
        break;
    
    default:
        $result = ['error' => ['code' => -32601, 'message' => 'Method not found']];
}

// Risposta JSON-RPC 2.0
echo json_encode([
    'jsonrpc' => '2.0',
    'result' => $result,
    'id' => $id
]);

function handleToolCall($tool, $args) {
    // Qui la tua logica business
    if ($tool === 'get_user') {
        return ['user' => ['id' => $args['id'], 'name' => 'Mario Rossi']];
    }
    
    if ($tool === 'create_order') {
        // INSERT INTO orders...
        return ['order_id' => 12345, 'status' => 'created'];
    }
    
    return ['error' => 'Tool not implemented'];
}
```

## ✅ MCP server in PHP (esempio minimo)

```php
<?php
// mcp-server.php

header('Content-Type: application/json');

// Leggi richiesta POST
$input = json_decode(file_get_contents('php://input'), true);

// Validazione JSON-RPC 2.0
if ($input['jsonrpc'] !== '2.0') {
    http_response_code(400);
    exit(json_encode(['error' => 'Invalid JSON-RPC version']));
}

$method = $input['method'];
$params = $input['params'] ?? [];
$id = $input['id'];

// Routing metodi MCP
switch ($method) {
    case 'tools/list':
        $result = [
            'tools' => [
                ['name' => 'get_user', 'description' => 'Leggi dati utente'],
                ['name' => 'create_order', 'description' => 'Crea ordine']
            ]
        ];
        break;
    
    case 'tools/call':
        $toolName = $params['name'];
        $args = $params['arguments'];
        
        // Chiama la tua logica
        $result = handleToolCall($toolName, $args);
        break;
    
    default:
        $result = ['error' => ['code' => -32601, 'message' => 'Method not found']];
}

// Risposta JSON-RPC 2.0
echo json_encode([
    'jsonrpc' => '2.0',
    'result' => $result,
    'id' => $id
]);

function handleToolCall($tool, $args) {
    // Qui la tua logica business
    if ($tool === 'get_user') {
        return ['user' => ['id' => $args['id'], 'name' => 'Mario Rossi']];
    }
    
    if ($tool === 'create_order') {
        // INSERT INTO orders...
        return ['order_id' => 12345, 'status' => 'created'];
    }
    
    return ['error' => 'Tool not implemented'];
}
```
