## Perché git status è incluso

OpenClaw include git status nel prompt per dare al modello contesto su:

**1. Awareness stato workspace**
- Branch corrente
- File modificati non committati
- File staged
- Conflitti merge

**2. Decisioni informate**
- "Ci sono modifiche non salvate?" → consiglia commit prima operazioni rischiose
- "Quale branch?" → sa dove stai lavorando
- "File nuovi?" → può suggerire .gitignore

**3. Git operations**
- Commit messages migliori (vede cosa è cambiato)
- Suggerimenti su staging
- Risoluzione conflitti

```bash

# O pulisci temp files

```

**3. Git clean (attenzione!)**

```bash
# Rimuovi untracked files (CAREFUL!)
git clean -fd --dry-run  # preview
git clean -fd            # execute
```

## Perché git status è incluso

OpenClaw include git status nel prompt per dare al modello contesto su:

**1. Awareness stato workspace**
- Branch corrente
- File modificati non committati
- File staged
- Conflitti merge

**2. Decisioni informate**
- "Ci sono modifiche non salvate?" → consiglia commit prima operazioni rischiose
- "Quale branch?" → sa dove stai lavorando
- "File nuovi?" → può suggerire .gitignore

**3. Git operations**
- Commit messages migliori (vede cosa è cambiato)
- Suggerimenti su staging
- Risoluzione conflitti

Ogni path è ~50-100 caratteri → con molti file untracked, git status diventa **migliaia di token**.

## Workaround pratici

**1. .gitignore più aggressivo**

Aggiungi pattern per ridurre untracked files:

```bash
# .gitignore
media/inbound/openclaw-staged-*
memory/2026-*.md
*.log
```

Questo riduce drasticamente output git status.

**2. Commit/cleanup regolare**

```bash
# Commit work in progress
git add .
git commit -m "WIP: checkpoint"

# O pulisci temp files
rm -rf media/inbound/openclaw-staged-*
```

**3. Git clean (attenzione!)**

```bash
# Rimuovi untracked files (CAREFUL!)
git clean -fd --dry-run  # preview
git clean -fd            # execute
```

## Non c'è config diretta

Ho cercato nella config schema e **non c'è un'opzione** `agents.defaults.includeGitStatus: false` o simile.

Il git status è hardcoded nel runtime context assembly. Sarebbe una buona feature request!

## Impatto stimato

Con il tuo workspace, git status pulito potrebbe risparmiare:
- **Attuale**: ~2-4k token (molti untracked)
- **Con cleanup**: ~500-1k token (solo essentials)

**Risparmio: ~1.5-3k token fresh per chiamata**

## Conclusione

**Sì, puoi controllarlo indirettamente:**
1. ✅ .gitignore → riduce untracked files
2. ✅ Commit regolari → meno modifiche pending  
3. ✅ Cleanup temp files → meno noise
4. ❌ No config diretta per disabilitarlo

**Perché serve:** Il modello usa git status per decisioni informate su commit, branch, conflitti. Ma con troppi file untracked diventa inefficiente.

**Best practice:** Mantieni workspace pulito + .gitignore completo.
