## 🔴 PRIORITÀ: Bloccare l'intruso

Il "trick" per multiple sessioni **non è la soluzione** — se un hacker ha accesso RDP, il tuo problema è che deve essere **fisicamente chiuso fuori**.

### 1. Disabilita RDP se non ti serve subito
```
Impostazioni → Sistema → Desktop remoto → OFF
```
Oppure da PowerShell (admin):
```powershell
Disable-NetFirewallRule -DisplayGroup "Remote Desktop"
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 1
```

### 2. Cambia subito la password dell'account
Password forte (20+ caratteri). Se hai account amministratore con password debole, è quello il punto di ingresso.

### 3. Blocca account non necessari
```powershell
# Vedi chi ha accesso RDP
Get-LocalGroupMember -Group "Remote Desktop Users"

# Rimuovi account sospetti
Remove-LocalGroupMember -Group "Remote Desktop Users" -Member "NOME_SOSPETTO"
```

### 4. Account Lockout Policy
```powershell
net accounts /lockoutthreshold:3 /lockoutduration:30 /lockoutwindow:30
```
Dopo 3 tentativi falliti → lock per 30 minuti. Bravo force bloccato.

### 5. NLA (Network Level Authentication)
Assicurati che sia attiva:
```
Impostazioni → Sistema → Desktop remoto → Impostazioni avanzate → 
"Richiedi ai computer di utilizzare l'autenticazione a livello di rete" → ON
```

### 6. Firewall — limita RDP al tuo IP solo
Se ti colleghi da reti note, restringi:
```powershell
# Rimuovi regola generale
Remove-NetFirewallRule -DisplayGroup "Remote Desktop"

# Crea regola solo per IP specifici (esempio)
New-NetFirewallRule -DisplayName "RDP-MioIP" -Direction Inbound -Protocol TCP -LocalPort 3389 -RemoteAddress "IL_TUO_IP" -Action Allow
```

### 7. Verifica porte/API backdoor
```powershell
# Vedi connessioni attive
netstat -ano | findstr ESTABLISHED

# Processi in ascolto
netstat -ano | findstr LISTENING
```

### 8. Controllo account nascosti
```powershell
Get-LocalUser | Select Name,Enabled,LastLogon
```
Guarda account che non riconosci o con last logon recente.

## RDPWrap

**Cos'è:** Libreria che patcha `termsrv.dll` senza modificare file di sistema — installa un wrapper che intercetta le chiamate e sblocca multi-sessione.

**Costo:** **Completamente gratuito e open source** (licenza Apache 2.0)

**GitHub:** `github.com/stascorp/rdpwrap`

### ⚠️ Stabilità

**Onestamente: non granché nel 2025-2026.** Ecco perché:

- Il progetto originale è **praticamente abbandonato** (ultimo release ufficiale: 2017)
- Va usato con i **RDP Wrapper Registry patches non ufficiali** della community per funzionare su Windows 11
- **Ogni Windows Update maggiore** (specialmente i cumulative mensili) può romperlo
- Su Windows 11 23H2/24H2 molti utenti riportano che smette di funzionare dopo gli update
- La community mantiene file `ini` aggiornati su fork come `github.com/sebaxakerhtcu/rdpwrap` (i file ini sono la "chiave" che dice al wrapper come patchare ogni versione di termsrv.dll)
- Quando si rompe: schermata nera, errore "Impossibile connettersi", o la patch semplicemente non ha effetto

**In sintesi:** funziona, ma è **fragile** e richiede manutenzione manuale. Non ci costruirei un workflow produttivo sopra.

## Alternative

### 1. 🟢 Tailscale + RDP (consigliata, gratis)
Non è multi-sessione, ma risolve il **vero problema**:

- **Gratis** per uso personale (fino a 100 device)
- Installi Tailscale sul PC target → ottiene un IP privato (100.x.x.x)
- Ti colleghi in RDP **solo tramite rete Tailscale**
- La porta 3389 **non è esposta a internet** → l'hacker non può raggiungerla
- Zero configurazione router/port-forwarding
- WireGuard sotto il cofano (veloce, sicuro)

**Questo ti protegge dall'intruso** molto meglio di RDPWrap.

### 2. 🟡 Windows Server (ufficiale, a pagamento)
- Windows Server 2022 supporta nativamente multi-sessione RDP con **Remote Desktop Services (RDS)**
- Licenza CAL richiesta (~€130-150 per utente)
- È la soluzione "corretta" enterprise
- Overkill per un singolo PC

### 3. 🟡 AnyDesk / TeamViewer / RustDesk (gratis per uso personale)
- **Multi-connessione simultanea** supportata nativamente
- Nessun limite di sessione attiva
- **RustDesk** è open source e self-hostable (più privacy)
- **AnyDesk** gratis per personale, a pagamento per commerciale
- Svantaggio: non è RDP nativo, ha il suo client
- **Per il tuo caso d'uso** (qualcuno che ti frega la sessione): questi tool permettono di vedere chi è collegato e non "rubano" la sessione come RDP

### 4. 🟡 Chrome Remote Desktop (gratis)
- Google, gratuito, multi-piattaforma
- Non supporta multi-sessione parallela però
- Meno features di AnyDesk/RustDesk

### 5. 🟢 Apache Guacamole (gratis, self-hosted)
- Gateway web per RDP/SSH/VNC
- Permette multiple connessioni simultanee al backend RDP
- Richiede un server Linux intermedio
- Setup più complesso ma potentissimo
- Anche qui non risolve il limite di licenza di Windows per RDP concorrente

## Cos'è

Apache Guacamole è un **gateway web per desktop remoto**. Niente client, niente software da installare sul PC da cui ti colleghi. **Usi il browser.**

Supporta **RDP, VNC, SSH, Telnet, Kubernetes** — tutto da una pagina web.

**Costo:** 100% gratuito, open source (Apache License 2.0)

---

## Architettura

```
[Tu — browser qualsiasi] 
        ↓ HTTPS
[Server Linux con Guacamole] 
        ↓ RDP (porta 3389 interna)
[PC Windows 11 — non esposto a internet]
```

Punti chiave:
- Il **server Guacamole** fa da proxy/middleman
- Il PC Windows **non espone RDP a internet** — solo il server Linux lo raggiunge
- Tu ti colleghi al server Guacamole via browser → lui inoltra la connessione RDP al PC
- **Multiple connessioni simultanee** al PC Windows tramite lo stesso gateway

⚠️ **Nota importante:** Guacamole permette multiple connessioni web simultanee al gateway, ma se il target è un Windows 11 Pro, il limite di una sessione RDP alla volta rimane (è Microsoft). Per avere **vero multi-sessione parallelo** su Windows desktop serve comunque RDPWrap o passare a Windows Server.

Quello che Guacamole ti dà però è:
- **Accesso sicuro da ovunque** senza esporre porte
- **Sessioni shadow** (più persone vedono lo stesso desktop)
- **Registrazione sessione** (puoi registrare cosa fa l'hacker se gli dai un'esca)
- **Autenticazione multipla** (2FA, LDAP, OpenID)
- **Audit log completo** (chi si collega, quando, da dove)

## Installazione (Ubuntu/Debian)

### Metodo rapido: Docker Compose (consigliato)

#### 1. Prerequisiti
```bash
sudo apt update && sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
```

#### 2. Crea la struttura
```bash
mkdir -p ~/guacamole/{init,drive,record}
cd ~/guacamole
```

#### 3. Inizializza il database
```bash
docker run --rm guacamole/guacamole /opt/guacamole/bin/initdb.sh --postgres > init/initdb.sql
```

#### 4. Crea `docker-compose.yml`
```yaml
version: '3'

services:
  guacd:
    image: guacamole/guacd
    restart: always
    volumes:
      - ./drive:/drive:rw
      - ./record:/record:rw

  postgres:
    image: postgres:16
    restart: always
    environment:
      POSTGRES_DB: guacamole_db
      POSTGRES_USER: guacamole_user
      POSTGRES_PASSWORD: CAMBIA…ORTE
    volumes:
      - ./init:/docker-entrypoint-initdb.d:ro
      - pgdata:/var/lib/postgresql/data

  guacamole:
    image: guacamole/guacamole
    restart: always
    ports:
      - "8080:8080"
    environment:
      GUACD_HOSTNAME: guacd
      POSTGRES_HOSTNAME: postgres
      POSTGRES_DATABASE: guacamole_db
      POSTGRES_USER: guacamole_user
      POSTGRES_PASSWORD: CAMBIA…ORTE
      # Opzionale: attiva 2FA con TOTP
      TOTP_ENABLED: "true"
    depends_on:
      - guacd
      - postgres

volumes:
  pgdata:
```

#### 5. Avvia
```bash
docker compose up -d
```

#### 6. Verifica
```bash
docker compose ps
```
Tutti e 3 i container devono essere `running`.

#### 7. Accedi
```
http://IP_DEL_SERVER:8080/guacamole/
```
**Credenziali default:**
- User: `guacadmin`
- Password: `guacadmin`

⚠️ **Cambia subito la password admin al primo login!**

## Sicurezza (importante per il tuo caso)

### Reverse proxy con HTTPS (obbligatorio se esposto a internet)
```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

Configura Nginx:
```nginx
server {
    server_name guac.tuodominio.it;

    location / {
        proxy_pass http://localhost:8080/guacamole/;
        proxy_buffering off;
        proxy_http_version 1.1;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 1d;
    }

    listen 80;
}
```

```bash
# Certificato HTTPS
sudo certbot --nginx -d guac.tuodominio.it
```

### 2FA (TOTP) — già abilitato nel compose sopra
Al primo login dopo aver abilitato TOTP, Guacamole ti fa scan di un QR code (tipo Google Authenticator). Da quel momento serve codice OTP + password.

### Firewall
```bash
# Solo HTTPS esposta
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# Mai esporre 8080 direttamente a internet!
sudo ufw enable
```
