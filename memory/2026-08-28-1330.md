### 1. MCP Write Tool (~50 righe)

```typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { VectorStoreIndex, Document } from "llamaindex";
import Anthropic from "@anthropic-ai/sdk";

const claude = new Anthropic({ apiKey: process.env.CLAUDE_KEY });
const index = await VectorStoreIndex.fromVectorStore(pgVectorStore);

mcpServer.tool({
  name: "create_doc",
  description: "Crea e indicizza documentazione da prompt",
  parameters: {
    topic: { type: "string", description: "Argomento doc" },
    detail_level: { type: "string", enum: ["basic", "detailed"] }
  },
  async handler({ topic, detail_level }) {
    // 1. LLM genera contenuto (Claude API - 5 righe)
    const content = await claude.messages.create({
      model: "claude-sonnet-4-6",
      max_tokens: 2000,
      messages: [{
        role: "user",
        content: `Scrivi documentazione ${detail_level} su: ${topic}`
      }]
    });
    
    const text = content.content[0].text;
    
    // 2. LLM genera metadati (opzionale - 5 righe)
    const metadata = await claude.messages.create({
      model: "claude-haiku-4-5",
      max_tokens: 200,
      messages: [{
        role: "user",
        content: `Genera titolo e 5 tag per:\n${text.slice(0, 500)}`
      }]
    });
    
    // 3. LlamaIndex indicizza (auto-chunking + embedding - 3 righe)
    const doc = new Document({ text, metadata: JSON.parse(metadata.content[0].text) });
    await index.insert(doc);
    
    return { 
      status: "indexed",
      doc_id: doc.id_,
      title: doc.metadata.title
    };
  }
});
```

## Approccio ibrido: Markdown + Vector Storage

**Markdown files** = source of truth (modificabile, versionabile, human-readable)  
**Vector DB** = indice di ricerca (veloce, semantico, AI-friendly)

### Vantaggi

1. **Modificabilità diretta**: utente può correggere/aggiornare markdown senza passare per AI
2. **Portabilità**: markdown resta leggibile anche senza piattaforma (no vendor lock-in dei dati)
3. **Version control**: file markdown in Git = storico completo modifiche
4. **Fallback**: se vector search fallisce, hai sempre i file originali
5. **Controllo qualità**: human review su contenuto generato da AI

### Architettura

```
User prompt → AI genera markdown → File .md salvato
                                ↓
                        LlamaIndex auto-sync → Vector DB
                                ↓
Query → Vector search → Risposta + link file markdown originale
```

### Implementazione (~50 righe extra)

**1. File watcher per auto-sync**
```typescript
import chokidar from 'chokidar';

chokidar.watch('knowledge/**/*.md').on('change', async (filepath) => {
  const content = await fs.readFile(filepath, 'utf-8');
  const doc = new Document({ 
    text: content, 
    metadata: { 
      source: filepath,
      last_modified: new Date()
    }
  });
  await index.insert(doc); // Auto-reindex
});
```

**2. Tool MCP Write restituisce path file**
```typescript
async handler({ topic, detail_level }) {
  const content = await claude.messages.create({...});
  
  // Salva file markdown
  const filepath = `knowledge/${topic.replace(/\s+/g, '_')}.md`;
  await fs.writeFile(filepath, content);
  
  // Indicizza in vector DB
  await index.insert(new Document({ text: content, metadata: { source: filepath }}));
  
  return { 
    status: "created", 
    file: filepath, // Utente può modificare direttamente
    indexed: true 
  };
}
```

**3. Search restituisce link file originale**
```typescript
async handler({ query }) {
  const result = await queryEngine.query(query);
  
  return {
    answer: result.response,
    sources: result.sourceNodes.map(n => ({
      text: n.node.text,
      file: n.node.metadata.source, // Link al .md originale
      score: n.score
    }))
  };
}
```

### Workflow utente

1. **AI genera doc**: `create_doc topic="Procedura qualità ISO9001"`  
   → File salvato in `knowledge/Procedura_qualita_ISO9001.md`  
   → Auto-indicizzato in vector DB

2. **Utente modifica manualmente**: apre file, corregge errore, salva  
   → File watcher rileva modifica  
   → Vector DB auto-aggiornato

3. **AI ricerca**: `search_docs query="Come fare audit qualità"`  
   → Vector search trova chunks rilevanti  
   → Risposta + link a `knowledge/Procedura_qualita_ISO9001.md`

### Vantaggi pratici

- **Trasparenza**: utente vede esattamente cosa c'è nella knowledge base (apre cartella, legge markdown)
- **Debug facile**: se AI risponde male, controlli file markdown e correggi
- **Migration semplice**: se cambi piattaforma, porti via i markdown
- **Git integration**: `git log knowledge/` mostra chi ha modificato cosa e quando

### Costi aggiuntivi

Zero. File markdown sono gratis, file watcher è libreria Node.js standard.

**In sintesi**: Markdown files come "database umano", vector DB come "indice AI". Best of both worlds.

## Embedding: due approcci

### 1. **Embedding tradizionali** (algoritmi puri, zero LLM)

**TF-IDF / BM25** (deterministici al 100%)
```python
# Algoritmo puro, no LLM, no API
from sklearn.feature_extraction.text import TfidfVectorizer

vectorizer = TfidfVectorizer()
vectors = vectorizer.fit_transform([
  "Procedura qualità ISO 9001",
  "Audit interno documentazione"
])
# Output: vettori numerici (frequenza parole)
```

**Pro:**
- ✅ Zero costi API
- ✅ Veloce (milliseconds)
- ✅ Deterministico (sempre stesso output)
- ✅ Funziona offline

**Contro:**
- ❌ **Ricerca solo keyword-based** (no semantica)
- ❌ "Procedura qualità" ≠ "Controllo standard" (non capisce sinonimi)
- ❌ Meno potente per domande naturali

---

### 2. **Embedding neurali** (modelli ML, NO API necessaria)

**Sentence Transformers self-hosted** (gratis, potente)
```python
from sentence_transformers import SentenceTransformer

# Modello gratis, self-hosted
model = SentenceTransformer('all-MiniLM-L6-v2')

# Genera embedding senza API
embeddings = model.encode([
  "Procedura qualità ISO 9001",
  "Controllo standard aziendale"
])
# Output: vettori semantici (capisce significato)
```

**Pro:**
- ✅ **Ricerca semantica** ("qualità" ≈ "standard")
- ✅ Zero costi API (self-hosted)
- ✅ Deterministico (stesso input = stesso embedding)
- ✅ Open source (MIT license)

**Contro:**
- ⚠️ Serve **RAM/CPU server** (modello ~80MB, inferenza CPU)
- ⚠️ Più lento di API cloud (100-500ms vs 50ms OpenAI)

---
